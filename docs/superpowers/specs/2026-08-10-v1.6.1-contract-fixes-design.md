# v1.6.1 Contract Fixes Design

## Goal

Repair two contract gaps without changing the fiction-writing method itself:

1. make the release integrity verifier match the assets actually published for v1.6.0 and later 1.x patch releases;
2. make whole-chapter rewrites use the same `prose-writing` Skill contract as first-pass prose generation.

## Scope

### Release verification

The verifier will recognize exactly these release ZIP roles for one version:

- `codex-novel-workflow-portable-v<version>.zip`
- `serial-fiction-workflow-v<version>-official.zip`
- `skill.zip`
- `writing-serial-fiction-v<version>.zip`

The checksum file remains `SHA256SUMS-v<version>.txt` and must list all four ZIPs exactly once. The two Skill ZIPs are allowed to be byte-identical, but each file name must still be present in the outer checksum file.

Portable-package validation keeps the existing inner `MANIFEST.sha256` rules. Repository-source and Skill archives use archive-shape checks appropriate to their role instead of being forced through the historical overlay/profile manifest rules.

### Whole-chapter rewrite

`工作流/04_修正.md` will continue to own repair routing and the one-rewrite limit. Only its `整章重写` branch changes: it must invoke `$writing-serial-fiction mode=prose-writing` with exactly the prose-minimal packet and scene execution card, apply the same `INPUT_ERROR:` / `BLOCKED:` / output-shape gates as the first-pass prose workflow, and then continue to one re-check.

Local patching and scene rewrite behavior remain unchanged.

## Testing

Add regression tests that fail on the current behavior and pass after the fix:

- synthetic release directories matching the four current ZIP roles are accepted;
- missing/extra checksum entries are rejected;
- unsafe or malformed ZIP members remain rejected;
- the whole-chapter rewrite section explicitly invokes `prose-writing` and supplies only the two approved inputs;
- later-stage tests no longer impose the blanket rule that workflow 04 may never invoke the Skill; workflow 03 remains Skill-free.

## Non-goals

- no v1.7 feature work;
- no changes to prose style guidance, chapter-planning heuristics, light-check thresholds, or state-machine limits;
- no automatic second repair loop;
- no repository-wide refactor.
