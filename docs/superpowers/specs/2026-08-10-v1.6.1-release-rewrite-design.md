# v1.6.1 Repair Design

## Goal

Repair the two confirmed contract gaps found in v1.6.0 without changing the novel-writing method itself, and reduce version/release drift with narrowly scoped tests.

## Scope

### 1. Release artifact verification

Update `tools/release_integrity.py` and its tests so the verifier matches the actual public v1.6.x release contract instead of the removed overlay/migration-profile contract.

The supported release directory must contain exactly these public artifacts for the current version:

- `codex-novel-workflow-portable-v<version>.zip`
- `serial-fiction-workflow-v<version>-official.zip`
- `skill.zip`
- `writing-serial-fiction-v<version>.zip`
- `SHA256SUMS-v<version>.txt`

Requirements:

- Verify every ZIP can be opened and has no duplicate or unsafe members.
- Verify the portable package against its inner `MANIFEST.sha256` using the existing strict manifest rules.
- Verify `skill.zip` and the versioned Skill ZIP are byte-identical in content and each contains the expected Skill root.
- Verify the repository-source ZIP is structurally safe; do not require the portable-package inner manifest contract for it.
- Verify `SHA256SUMS-v<version>.txt` contains exactly the four ZIP artifact names and matching SHA-256 digests.
- Keep verification offline and deterministic.
- Update the CLI success message to report the actual number of verified ZIP artifacts.

### 2. Whole-chapter rewrite uses the prose Skill

Keep local patching and scene rewriting in `工作流/04_修正.md`, but make the `整章重写` branch reuse the same writing executor as initial prose generation:

- only read `工作区/第N章_正文最小包.md` and `工作区/第N章_场景执行卡.md`;
- explicitly call `$writing-serial-fiction mode=prose-writing`;
- apply the same `INPUT_ERROR:`, `BLOCKED:`, Skill-load-failure, and output-shape failure gates as initial generation;
- preserve the old failed draft before replacement;
- increment `修正次数` only after a valid replacement draft is saved;
- run one independent light-check afterward.

The integration test must no longer assert that all of workflow 04 is Skill-free. Instead it must assert that local patch/scene-rewrite paths do not invoke the Skill while the whole-chapter rewrite path does.

### 3. Version as a single source of truth

Do not bump the repository to v1.6.1 in this repair branch yet. Keep `VERSION` as `1.6.0` until release preparation.

Reduce avoidable duplication by changing CI/tests that can safely derive the current version from `VERSION` instead of asserting a separately hard-coded current version. Historical changelog/release-note checks may continue to mention v1.6.0 where they intentionally verify a historical artifact.

### 4. Demo wording correction

Adjust public wording that currently implies a completed two-chapter demo. Describe v1.6.0 as a complete single-chapter workflow demo/foundation, while leaving the two-chapter continuous demo as a v1.7 roadmap item.

## Non-goals

- No rewrite of the planning/prose/diagnosis writing methodology.
- No state-machine redesign.
- No new multi-agent architecture.
- No automatic GitHub Release publishing in this patch; only make the verifier contract correct and testable. Release automation can be a separate follow-up.
- No v1.7 feature work.

## Testing

Add or update tests before implementation where practical:

1. release verifier accepts a synthetic directory matching the four-ZIP v1.6.x contract;
2. missing/extra checksum entries fail;
3. mismatched Skill archives fail;
4. unsafe ZIP members fail;
5. whole-chapter rewrite explicitly invokes `mode=prose-writing` and preserves isolation;
6. local patch and scene rewrite remain Skill-free;
7. CI derives the current version from `VERSION` rather than duplicating `1.6.0` in shell logic;
8. full `python -m pytest -q -p no:cacheprovider` passes.

## Delivery

Implement on `fix/v1.6.1-release-rewrite`, verify the full suite, inspect the final diff, then open a draft pull request against `main`. Do not merge automatically.
