# Readonly diagnosis

## 输入

必须提供非空的待评估正文。章节目标、主要兑现和结尾落点为可选参照。

文本缺失时只返回：

`INPUT_ERROR: missing=待评估正文`

## 诊断边界

只读输入文本，不打开其他文件或网站，不修改、续写或重写原文，不触发规划、轻检、
修正、文件保存或状态变化。

只报告有具体证据并会明显影响理解、推进、兑现、代入或人物辨识的问题。同一根因
造成的相邻表现合并为一项，用最少证据说明，不逐句挑错。区分：

- **硬冲突**：只依据调用方明确提供的目标、结果或结尾判断；
- **读者体验信号**：属于可选改进，不冒充事实错误。

不要为找问题而挑主观文风，不要求无条件润色，不使用固定词频、句长或爽点数量
作为通过标准。所谓“AI感”不按某个词判定，只在重复结构和叙事行为有成片证据时报告。
没有明显问题时直接说明。

## 检查信号

- 承诺是否得到事件或状态变化回应；提供固定结果时，承诺是否超过本章实际可达范围；
- 相邻场景是否由结果推动，而非可随意换序；
- 多个小场面是否只是用不同物品反复证明同一规则或同一“仍未解决”状态，却没有新后果；
- 重要结果后是否先由在场人物的即时反应或行动变化承接；
- 动作、对白或结果已证明后，旁白是否重复概述同一事实、风险或边界；当前决定已经得到充分支持后，是否仍继续补证；
- 是否频繁出现“只能说明／不能证明／不等于／并不代表”等连续免责声明，使小说像事故报告；
- 状态数字是否只在首次出现、实际变化或影响当前选择时呈现；不同状态字段是否被依次报出而组成审计台账，未变化数值是否也被显式列出；同一次交易、消耗或收益是否在一个位置结算后又反复报相同数值；
- 连续状态、禁区或知情限制是否泄漏成连续免责声明；
- 设定、技术、界面或规则是否按当前行动所需逐步出现，是否压过人物选择与后果；
- 视角人物是否混淆亲见、他人陈述与推断；
- 重要人物的对话是否真正回应并可区分，是否都使用同一种完整分析语气、定义句或合同式表达；
- 限知是否被写成没有主观判断的摄像机，使视角人物失去自己的欲望、偏差或可错的工作假设；视角人物是否主要承担解释规则、主持协商和给出标准答案；
- 执行卡中的“目标、边界、状态变化、可行性、候选、确认条件”等规划语言是否直接泄漏进叙述或人物对白；
- 情绪是否有选择、动作或感知证据；
- 景物和身体细节是否参与判断，还是只作为通用晨光、灰尘、心跳、握拳装饰；
- 高潮或结算后是否重复解释、复盘或延长不改变结果的善后；
- 固定结尾前是否集中回收多个未决状态；章末是否精确落到给定结尾；作为冲击的异常、选择、后果或概括句是否已在前文被多次预支。

## 输出

有问题时直接从第一项 `位置` 开始逐项输出，不添加总体结论、无硬冲突声明、前言、摘要或评分：

```text
位置：章节或段落位置
类型：硬冲突／读者体验
可观察证据：不超过两处原文短摘录
对阅读推进的影响：一句话
最小调整方向：只说明调整方向，不代写
```

优先报告能通过删除、合并或缩短解决的根因；不要把同一“解释过度”拆成多项。

没有明显问题时输出：

`未发现有充分证据的明显问题。`
